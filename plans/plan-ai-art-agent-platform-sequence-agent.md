# AI 美术智能体平台：动画与特效统一智能体闭环

## 需求描述

在现有动画/特效序列生产管线之上完成方案 B，使 `animation` 与 `effect`
进入和静态资产一致的阶段式智能体闭环：

```text
序列需求与参考上下文
→ LLM 结构化规划
→ 用户检查并修改计划/提示词
→ 整条序列单次生成或编辑
→ 本地固定网格处理与硬约束检查
→ LLM 可解释视觉评审
→ 用户显式触发最多两次整条序列定向修复
→ 选择候选
→ 风格风险确认
→ 无覆盖导出
```

本方案只补齐动画/特效缺失的规划、评审、定向修复和导出风险门禁，继续复用
阶段 7 已完成的网格、切分、共享缩放、锚点/基线、Sprite Sheet、GIF/WebP
与漂移检查基础设施，复用阶段 8 已完成的 `GenerationPlan`、`QualityReport`、
`RepairPlanner`、供应商审计和费用记录。

### 当前缺口

现有 `SequenceProductionService` 直接使用默认提示词调用 `ImageProvider`，没有：

- `GenerationPlan` 或生成前计划预览。
- 项目风格圣经、显式参考图和角色身份摘要上下文。
- 视觉评审、评分解释、比较板和风险提示。
- 自动定向修复、父子运行关系和停止原因。
- 风格阈值导出门禁。

现有测试还明确断言序列生产不会使用 `ReviewProvider`。该行为将在方案 B 中被替换，
但旧运行记录仍必须可读取、预览、重新离线处理和导出。

## 方案选择

### 方案 1：基线先行并增量扩展（采用）

先将平台基础源码、测试、配置、Schema、预设和启动脚本纳入版本控制，再以独立提交
实现方案 B。优点是每个提交可独立检出、测试和审查；缺点是增加一笔纯基线提交。

平台基础基线已由提交 `4e98315` 建立，并明确忽略 `.env`、工作数据、Pilot 产物和
Playwright 结果。

### 方案 2：将基础文件混入方案 B

可以得到可运行结果，但既有平台与新功能混在同一批变更中，无法准确审查方案 B，
也不利于回退。因此不采用。

### 方案 3：继续依赖未跟踪文件

当前 `HEAD` 缺少前后端清单、入口、路由、配置、供应商和启动脚本，重新检出后无法
运行。该方案不满足可复现要求，因此拒绝。

## 实现方案

### 1. 架构原则

方案 B 不创建第二套自由运行 Agent，也不把静态资产服务强行泛化为复杂继承体系。
采用组合方式：

- `SequenceProductionService` 继续负责序列网格、模型条带、确定性处理、运行持久化和导出。
- 公共 `ReviewProvider` 继续负责结构化规划和视觉评审。
- 公共 `RepairPlanner` 继续把明确失败维度转换为定向修改指令。
- 新增轻量序列上下文适配器，将 `SequenceTask` 映射为公共 `AssetTask`，并附带帧数、
  网格、锚点、循环和基准帧等序列专属上下文。
- 新增序列硬约束适配器，将本地漂移报告和输出规格转换为公共
  `HardConstraintReport`。模型不得覆盖本地硬约束结论。

这样既复用统一智能体协议，又不改写已经稳定的静态生产闭环。

### 2. Schema 与兼容策略

`SequenceTask` 新版本增加：

- `brief`：自然语言需求。
- `usage`：游戏内用途。
- `style_pack`：项目风格包标识。
- `reference_ids`：用户显式选择的 0–4 张项目参考图。
- `constraint_profile`：序列约束预设标识。
- `candidate_count`：1–4 个候选。
- `output_mode`：逐帧、Sprite Sheet 或组合导出语义。
- `character_asset_id`：动画所依赖的已批准角色身份；特效为空。

`SequenceTask.schema_version` 扩展为版本 2。读取版本 1 时使用兼容默认值，不重写旧文件：

- 旧动画继续使用已保存的 `base_frame_workspace_relative_path`。
- 旧任务没有 `character_asset_id` 时不强行推断路径，只缺少身份摘要上下文。
- 旧任务没有显式参考图时使用空列表。
- 旧任务的默认提示词仍可用于预览和重新离线处理，但新的模型生成必须先规划。

`GenerationPlan` 增加可选 `sequence_spec`。当 `asset_type` 为 `animation` 或 `effect` 时，
该字段必填，内容固定包括：

- 帧数、行列和模型生成单格尺寸。
- 最终单帧尺寸、FPS 和循环设置。
- 基线、Pivot、共享缩放和首帧锁定要求。
- 动作方向、帧顺序和身份连续性要求。

静态资产的 `sequence_spec` 必须为空，避免改变现有静态计划语义。

`SequenceCandidate` 增加：

- 本地 `hard_constraints`。
- `quality_report`。
- `comparison_relative_path`。
- `revised_prompt`。

`SequenceRun` 新版本增加：

- `plan`。
- `source_run_id`、`source_candidate_id` 和 `edit_instruction`。
- `review_attempts` 与 `auto_repair_summary`。
- `last_error`，只保存可展示的脱敏错误，不保存密钥和供应商原始敏感信息。

运行状态扩展为：

```text
reference_ready
planning
planned
generating
processing
processed
selected
reviewing
reviewed
needs_input
exporting
exported
failed
```

版本 1 的 `generated` 状态继续允许读取，并按“已有原始候选、等待处理”解释。

### 3. 规划上下文

新增 `SequenceAgentContext`，作为 `PlanningRequest` 和 `ReviewRequest` 的可选字段。
公共 `ReviewProvider` 方法签名保持不变，避免供应商接口分叉。

规划请求包含：

- 项目配置和完整风格圣经。
- 由序列任务映射得到的公共 `AssetTask`。
- 最多 4 张显式参考图及标签说明。
- 动画角色身份摘要和已批准基准帧说明。
- 模型请求画布与最终导出画布。
- 网格、帧数、动作、FPS、循环、基线、Pivot 和首帧锁定要求。
- 不得逐帧独立生成的明确约束。

规划结果必须满足：

- `asset_type` 与序列类别一致。
- `selected_reference_ids` 只能来自任务允许的参考图。
- `sequence_spec` 与任务的硬性网格和尺寸完全一致。
- 模型提示词明确要求一次生成完整二维条带、帧顺序可读、槽位不合并。

任何不一致都作为规划格式错误处理，不进入图像模型调用。

### 4. 生成数据流

新序列固定按以下步骤执行：

1. 用户填写需求、角色基准、参考图和序列规格。
2. 服务创建版本 2 任务和固定参考网格，状态为 `reference_ready`。
3. 用户点击“生成计划”，调用一次 `ReviewProvider.plan`。
4. 服务校验并保存 `plan.json`，状态为 `planned`。
5. 用户查看计划并可修改生成提示词，但不得直接修改网格硬规格。
6. 用户点击生成，服务检查模型画布合法性和候选数上限。
7. 动画调用一次 `ImageProvider.edit`；特效调用一次 `generate` 或 `edit`。
8. 每个候选返回一张完整二维条带，随后全部步骤在本地处理。
9. 服务保存原始条带、逐帧 PNG、Sprite Sheet、GIF/WebP 和漂移报告。
10. 服务生成本地硬约束报告并进入 `processed`。

无论初次生成还是自动修复，每个候选每次只允许一次完整条带模型调用。任何实现和测试
都不得按帧循环调用供应商。

### 5. 序列视觉评审

新增确定性的 `SequenceReviewBoardBuilder`：

- 顶部展示带帧号和方向标识的完整 Sprite Sheet。
- 动画展示已批准基准帧和角色身份摘要。
- 下方展示最多 4 张项目参考图及其标签。
- 特效展示首帧、中间帧、尾帧和完整 Sprite Sheet，辅助判断首尾连续性。
- 所有布局、缩放、背景和标签顺序固定，重复生成字节稳定。

评审请求包含序列对比板和本地漂移摘要。模型负责：

- 角色身份、服饰、面部和主色连续性。
- 水墨线条、配色和 2.5D 俯视语义。
- 动作方向、帧顺序和姿态可读性。
- 特效的形态演进、亮度节奏和首尾语义。

服务端随后覆盖模型返回的硬约束部分：

- 帧数、尺寸、网格整除和 RGBA。
- 透明残留和边界溢出。
- 中心、尺寸、基线、面积、主色和亮度漂移。
- Sprite Sheet 与逐帧输出哈希一致性。

`QualityReport.animation_review` 使用本地度量值，模型只能补充可见问题说明，不能修改
数值或通过状态。

### 6. 自动定向修复

自动修复必须由用户显式点击，默认最多两次。固定规则：

- 硬约束失败时不调用图像模型，返回 `manual-review-required`，提示先调整网格、约束或
  执行离线重新处理。
- 风格低分但没有明确可见证据时返回 `no-actionable-failure`。
- 达到两次上限时返回 `retry-limit-reached`。
- 只有身份、配色、线条、构图或动画一致性存在可操作证据时，
  `RepairPlanner` 才能生成编辑提示词。

每次修复创建新的子运行，不覆盖原运行：

- 输入主图为当前候选的完整原始条带。
- 动画同时提供原参考网格，并最多补充两张项目参考图。
- 特效提供当前原始条带，并最多补充三张项目参考图。
- 单次 `ImageProvider.edit` 返回一张新的完整条带。
- 新条带重新执行完整本地处理、硬约束和视觉评审。
- 父子运行、候选、修复提示词、评审、停止原因和费用记录全部持久化。

修复提示词必须明确保持网格、帧数、槽位顺序、角色身份和未失败维度不变，不允许要求
模型重新设计整个动作或拆分成逐帧请求。

### 7. API 设计

在现有 `/api/v1/projects/{projectId}/sequences` 路由下增加：

- `POST /{category}/{assetId}/runs/{runId}/plan`
- `POST /{category}/{assetId}/runs/{runId}/review`
- `POST /{category}/{assetId}/runs/{runId}/review-and-repair`
- `GET /{category}/{assetId}/runs/{runId}/candidates/{candidateId}/comparison`

现有生成、选择、重新处理、历史读取和工件读取接口保持兼容。

导出接口改为接收 `SequenceExportRequest`：

- `accept_style_risk=false` 为默认值。
- 硬约束失败始终禁止导出。
- 没有质量报告时禁止新版本运行导出。
- 风格分低于项目阈值时，只有显式接受风险才能导出。
- 版本 1 历史运行继续按原漂移门禁导出，界面必须标记“历史运行未经过模型风格评审”。

### 8. 前端设计

`SequenceCard` 保留现有网格、尺寸和动画预览功能，并增加四个连续区域：

1. 需求与上下文：需求描述、用途、角色身份、基准帧、0–4 张参考图。
2. 规划：生成计划按钮、构图/视角/光照/身份约束/后处理/检查项和可编辑提示词。
3. 候选与评审：候选 Sprite Sheet、漂移报告、风格分、分维度证据和比较板。
4. 修复与导出：最多两次费用提示、修复历史、停止原因、风格风险复选框和导出按钮。

交互规则：

- 未规划时禁用模型生成。
- 画布非法时在任何付费调用前阻止请求。
- 进入生成后参考图和角色身份锁定；需要调整时创建新运行。
- 没有明确可操作失败时禁用自动修复按钮。
- 历史版本 1 运行可预览和导出，但不伪造计划或评审结果。
- 项目切换时清除不匹配的序列草稿、打开目标和运行状态。

### 9. 错误处理与安全

- 规划 Schema 不匹配、类别不匹配或网格不一致：保存脱敏错误并返回稳定 409/422，
  不调用图像模型。
- 超时和限额：沿用供应商瞬时错误分类，可由用户重新执行当前阶段。
- 内容拒绝：标记 `needs_input`，不自动重试。
- 图像格式异常或候选为空：标记 `failed`，保留请求审计和已有原始文件。
- 本地硬约束失败：保留候选并禁止导出，不自动调用模型。
- 自动修复中断：已完成的父运行和子运行均保留，刷新后可恢复。
- 所有路径继续通过 `safe_child` 和 slug 校验，参考素材源保持只读。
- API Key 仅在后端 `.env` 中读取，不进入任务、计划、错误、前端响应或日志。

### 10. 测试与验收

后端必须覆盖：

- 版本 1 序列任务和运行记录兼容读取。
- 版本 2 Schema、序列计划一致性和最多 4 张参考图。
- 动画身份摘要、基准帧和参考图进入规划上下文。
- 规划完成前零次图像模型调用。
- 每个初始候选只调用一次完整条带生成/编辑。
- 每次自动修复只调用一次完整条带编辑，整条链最多两次。
- 任何路径都不存在逐帧供应商调用。
- 本地硬约束覆盖模型返回结果。
- 无明确失败证据、硬约束失败和内容拒绝不会盲目重试。
- 父子运行、评审、比较板、费用和停止原因刷新后可恢复。
- 风格风险和硬约束导出门禁。

前端必须覆盖：

- 需求、参考图、计划、候选、评审、修复和导出完整状态迁移。
- 非法画布和未规划状态在模型费用前被阻止。
- 评分证据、漂移报告、重试历史和停止原因可见。
- 版本 1 历史运行兼容展示。
- 项目切换隔离。

离线 Playwright 场景必须覆盖：

```text
创建动画任务
→ 选择角色基准和参考图
→ 生成并修改结构化计划
→ 生成四个假候选
→ 选择一个候选
→ 查看硬约束和风格评审
→ 执行一次定向修复
→ 恢复子运行与评审历史
→ 接受或拒绝风格风险
→ 导出规范序列
```

同样覆盖一个特效任务，并断言没有真实 OpenAI 请求。

全量门禁包括：

- 后端 pytest、Ruff 和 Mypy。
- 前端 Vitest、TypeScript、Vite 和 Playwright。
- 共享 Schema 连续生成哈希一致。
- 离线 Pilot 保持通过，只读素材哈希不变。
- 环境检查和无密钥启动冒烟通过，端口释放。
- 暂存区只包含方案 B 文件，不纳入 Pilot 输出、测试产物和 Unity 改动。

## 范围边界

方案 B 不包括：

- 真实 OpenAI 生成和 70% 四候选采用率统计。
- Unity Editor 导入、Play Mode 动画节奏和整体风格验收。
- 方案 C 的人工采用、返工原因和 Unity 验收记录界面。
- Unity 插件、自动导入、材质、Prefab 或动画控制器生成。
- 逐帧独立模型生成、骨骼动画或视频模型。
- 修改只读参考素材源、Unity Scene、Prefab、玩法代码或三条核心时间规则。
