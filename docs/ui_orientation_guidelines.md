# UI 横竖屏双布局规范

## 1. 目的

本项目后续新增或调整主要 UI 时，必须同时提供横屏和竖屏两套布局，保证电脑浏览器、手机浏览器以及后续 Android/iOS 版本都能正常操作。

两套布局只负责界面排列，不复制玩法数据、按钮事件或业务逻辑。

## 2. 核心规则

1. 每个主要 UI 都要设计横屏版和竖屏版。
2. 横竖屏共用同一份状态、数据和交互逻辑。
3. UI 根据画布当前实际宽高自动选择布局：
   - `Screen.height > Screen.width`：使用竖屏布局。
   - `Screen.width >= Screen.height`：使用横屏布局。
4. 不得仅依赖 `Screen.orientation` 或设置中的方向偏好判断当前布局。
5. 图标、字体、颜色、背景、通用按钮和面板资源应尽量复用。
6. 横屏与竖屏可以调整控件的位置、尺寸、排列方向和信息优先级。
7. UI 切换不得改变游戏流程、战斗状态、倒计时或玩家数据。

## 3. 推荐结构

使用 Canvas、Prefab 或 UI Toolkit 时，推荐保留两个布局根节点：

```text
ScreenName
├── SharedController
├── LandscapeRoot
└── PortraitRoot
```

- `SharedController`：读取游戏数据、刷新文本、处理按钮事件。
- `LandscapeRoot`：横屏排列，参考尺寸为 `960 × 540`。
- `PortraitRoot`：竖屏排列，参考尺寸为 `540 × 960`。

切换方向时，只启用符合当前画布比例的根节点。

如果界面继续使用 IMGUI，则应把横屏和竖屏的 Rect 计算分别放在清晰的布局方法中，例如：

```csharp
if (ResponsiveGui.IsPortrait)
{
    DrawPortraitLayout();
}
else
{
    DrawLandscapeLayout();
}
```

不要在同一个绘制方法中散落大量难以维护的横竖屏条件。

## 4. 必须覆盖的界面

下列界面新增或调整时，都必须检查横屏和竖屏：

- 主地图 HUD。
- 虚拟摇杆和移动端操作按钮。
- 设置界面。
- 角色状态界面。
- 装备与背包界面。
- 普通战斗界面。
- Boss 战界面。
- 隐藏洞穴界面。
- 武学或奖励三选一界面。
- 结算界面。
- 暂停、提示和确认弹窗。

## 5. 横屏布局原则

- 充分利用左右空间，将战斗双方、属性信息或功能区横向排列。
- HUD 尽量靠近四角，减少对地图中心区域的遮挡。
- 虚拟摇杆放在安全区左下方，主要操作按钮放在安全区右下方。
- 弹窗避免过高，优先使用左右分栏或横向按钮组。
- 电脑端鼠标、键盘操作和手机触摸操作都要可用。

## 6. 竖屏布局原则

- 重要信息按从上到下的阅读顺序排列。
- HUD 优先展示倒计时、气血和当前关键成长信息。
- 虚拟摇杆和操作按钮不能遮挡角色、敌人或关键地图入口。
- 较宽的横向面板应改为纵向列表、分页或滚动区域。
- 弹窗按钮应放在拇指容易触达的区域。
- 不得简单压缩横屏 UI，导致文字、按钮或血条过小。

## 7. 移动端交互要求

- 常用触摸区域建议不小于 `44 × 44` 个逻辑单位。
- 按钮按下后要有明确的颜色、缩放或声音反馈。
- 所有重要控件必须位于 `Screen.safeArea` 内。
- 不依赖鼠标悬停才能获得关键信息。
- 避免把高频按钮放在刘海、圆角、系统手势区或浏览器工具栏附近。
- 横竖屏切换后，弹窗、选中状态和游戏进度必须保留。

## 8. WebGL 横竖屏规则

Unity Play 和其他 WebGL 页面中的游戏画布由浏览器窗口决定。

- 电脑浏览器通常显示横屏布局。
- 手机浏览器通常显示竖屏布局。
- 玩家旋转手机并使浏览器画布宽高发生变化后，UI 自动切换。
- `Screen.orientation` 不能保证强制旋转 WebGL 浏览器。
- 浏览器全屏和方向锁定只能作为尽力尝试，不能作为 UI 正常显示的前提。
- 如果浏览器拒绝横屏锁定，应提示玩家关闭系统方向锁定并横置手机。
- 设置界面不能承诺所有 WebGL 手机都能通过按钮立即完成物理转屏。

## 9. 方向设置的职责

方向设置负责表达玩家偏好，但最终布局必须服从实际画布比例。

推荐行为：

1. 玩家点击横屏或竖屏。
2. 原生 Android/iOS 版本尝试设置 `Screen.orientation`。
3. WebGL 版本尝试请求全屏和浏览器方向锁定。
4. 等待实际宽高变化。
5. 实际变为横屏或竖屏后，启用对应布局。
6. 如果切换失败，保持当前可用布局并显示操作提示。

不得只改变按钮选中状态，却继续显示“已经完成转屏”的提示。

## 10. 开发验收清单

每个主要 UI 完成后至少检查：

- Unity Game View `960 × 540` 横屏布局。
- Unity Game View `540 × 960` 竖屏布局。
- 宽屏电脑浏览器中的 WebGL。
- 窄屏手机浏览器中的 WebGL。
- 手机横置和竖置后的实时布局切换。
- 刘海屏或带底部手势区设备的安全区。
- 中文文字没有截断、重叠或溢出。
- 按钮、摇杆和弹窗可以正常触摸。
- 切换布局后，倒计时、血量、选择状态和游戏阶段没有重置。

## 11. 核心玩法规则

UI 横竖屏切换不得改变以下三条规则：

1. 普通地图碰怪战斗时，主地图 60 秒倒计时继续流逝。
2. 隐藏洞穴内战斗时，主地图 60 秒倒计时暂停。
3. 最终 Boss 战不受 60 秒限制，独立计算 Boss 战时间。
