# 个人 2D 游戏资产智能体平台 Tauri 重构设计

## 1. 设计结论

将现有 `Tools/AiArtAgentPlatform/` 从 React/Vite + FastAPI 本地双进程工作台，重构为 React/Vite + Tauri 的 Windows 单机应用。

目标产品不是通用 AI 创作社区，也不是多模型聚合平台，而是面向个人独立游戏开发者的本地 2D 游戏资产生产工作台。平台以项目风格一致性、可追踪候选、确定性规格处理和 Unity 可用导出为核心，并明确使用 `gpt-image-2` 完成图片生成和编辑。

最终产品不启动 FastAPI，不监听 HTTP 端口，不要求用户安装或维护 Python 服务。React 负责网页式交互，Tauri 本地核心负责安全凭据、OpenAI 调用、任务调度、文件工作区、图像处理和导出。

## 2. 产品目标与边界

### 2.1 目标用户

- 单人或小型独立游戏开发者。
- 主要在 Windows 本机工作。
- 需要快速生产风格统一的 2D 游戏资产。
- 希望直接得到 PNG、逐帧 PNG、Sprite Sheet 和预览文件，而不是只得到概念图。

### 2.2 V1 资产范围

平台保留六类资产入口：

- `character`：角色原画、游戏内基准帧和角色变体。
- `scene`：2.5D 俯视角背景、地图块和分层场景元素。
- `item`：世界内 Sprite、武器、道具和掉落物。
- `ui`：图标、按钮、面板和装饰件。
- `animation`：角色逐帧动画和 Sprite Sheet。
- `effect`：透明逐帧特效和 Sprite Sheet。

实施顺序采用静态资产优先：先完成角色、场景、道具、UI 的完整闭环，再迁移动画和特效序列。

### 2.3 排除范围

V1 不实现：

- 登录、多用户、团队权限、云同步和在线协作。
- 社区、公开作品、模型市场和模板商城。
- LoRA、微调、自训练、私有 GPU 和模型托管。
- 多模型聚合首页和供应商市场。
- 完整无限画布、节点编排和 Photoshop 级编辑。
- Unity 插件、自动导入、Scene/Prefab 修改和玩法代码修改。
- 后端数据库、常驻 HTTP 服务和远程访问。

## 3. 主流产品取舍

主流平台提供了大量通用能力，但本产品只吸收与个人游戏资产生产直接相关的部分。

| 平台 | 借鉴能力 | 不进入 V1 |
| --- | --- | --- |
| Scenario | 项目风格、游戏资产分类、批量候选 | 团队工作流和模型训练 |
| Leonardo | 参考图控制、候选比较、蒙版编辑 | 通用创作门户和复杂模式切换 |
| Recraft | 项目历史、色板、编辑和导出 | 完整无限画布和矢量设计器 |
| Adobe Firefly | 风格参考、结构参考、生成填充 | Adobe 云生态和协作审批 |
| Krea | 快速反馈、任务进度、生成后继续编辑 | 多模型市场和实时生成为主的工作流 |
| OpenArt | 角色一致性、局部重绘 | 社区、训练中心和公开模型 |

由此确定 V1 采用“资产任务工作流 + 候选对比 + 局部轻量画布”。聊天输入只帮助整理需求，不成为独立聊天产品；无限画布不成为主导航。

## 4. 核心交互设计

### 4.1 主流程

```text
项目与风格包
-> 创建资产任务
-> 填写需求与选择参考图
-> 检查结构化计划和生成参数
-> 调用 gpt-image-2 生成 1-4 个候选
-> 候选对比、质量检查和人工选择
-> 局部编辑、蒙版重绘或重新生成
-> 确定性规格处理
-> Unity 资产导出
```

### 4.2 信息架构

主窗口采用稳定的工作软件布局：

- 左侧导航：项目、六类资产、任务历史、导出中心和设置。
- 顶部工具栏：当前项目、风格包、模型状态、活动任务和已知用量。
- 中央工作区：当前生产步骤、候选网格或编辑画布。
- 右侧检查器：参考图、提示词、模型参数、资产规格和质量报告。
- 底部任务抽屉：运行状态、失败原因、取消、重试和恢复记录。

不使用单页堆叠所有功能的首页。项目选择后直接进入最近工作区；没有项目时进入项目创建流程。

### 4.3 页面结构

#### 项目中心

- 创建、选择、重命名和归档本地项目。
- 选择内置“Q 版水墨武侠俯视角”风格预设。
- 显示最近资产和中断任务。
- 不显示营销内容、社区内容或无关模板。

#### 风格包

- 编辑风格圣经、色板、视角、主光方向、材质和禁止项。
- 浏览只读参考素材源，并将选中参考复制到项目工作区。
- 使用缩略图、标签和用途筛选参考图。
- 参考素材源始终只读。

#### 资产工作台

- 选择资产类别和用途。
- 以自然语言填写需求，系统转换为结构化字段。
- 选择 0-4 张显式参考图。
- 设置候选数、模型画布、质量和最终输出规格。
- 付费调用前确认模型、尺寸、质量和候选数。

#### 候选对比

- 以稳定网格并排展示最多 4 个候选。
- 同屏展示关键参考图、硬约束结果和风格评审。
- 支持选择、拒绝、收藏、局部编辑和基于候选继续生成。
- 硬约束和风格建议分开显示，模型不得覆盖本地硬约束结论。

#### 轻量编辑器

- 提供裁切、缩放、透明留白和背景透明化。
- 提供画笔蒙版、矩形蒙版和局部重绘。
- 提供扩图所需的画布调整。
- 不加入图层系统、复杂滤镜、矢量路径或完整绘图软件能力。

#### 序列工作台

- 展示模型网格、最终 Sprite Sheet 和逐帧播放。
- 提供 FPS、循环、帧号、锚点、脚底基线和漂移曲线。
- 动画必须从已批准角色基准帧开始。
- 每个候选整条序列只调用一次图像模型，禁止逐帧独立生成。

#### 导出中心

- 导出规范 PNG、逐帧 PNG、Sprite Sheet、GIF/WebP 和质量报告。
- 导出前检查尺寸、Alpha、命名、主体边界、Pivot 语义和网格。
- 默认拒绝覆盖已有文件，并记录输出哈希。

#### 设置

- 管理 API Key、模型状态、工作区路径、默认质量和超时。
- 显示供应商返回的已知用量；无法确定金额时标记“费用未知”。
- 提供手动模型可用性测试，不在应用启动时产生模型调用。

## 5. 视觉与响应式原则

- 定位为安静、紧凑、适合重复操作的生产工具。
- 使用宣纸白、墨黑、青绿色、暖灰和朱红强调色，避免单一米色或深蓝配色。
- 主工作区使用全宽无框布局，卡片只用于候选、任务条目和弹窗。
- 卡片圆角不超过 8px，不嵌套卡片。
- 工具命令优先使用 Lucide 图标，并为不熟悉的图标提供 Tooltip。
- 文本字号固定分级，不随视口宽度缩放。
- Windows 桌面优先支持 1366x768、1920x1080 和 2560x1440。
- 窄窗口隐藏右侧检查器为抽屉，中央画布保持最小可用宽度。

## 6. 技术架构

### 6.1 总体结构

桌面运行时采用 Tauri 2。Rust 基础依赖以 `tokio`、`reqwest`、`serde`、`keyring` 和 Rust 图像处理库为主，具体版本在实施计划中按当前稳定兼容版本锁定。

```text
React + TypeScript + Vite
  -> PlatformGateway
  -> Tauri invoke / event
  -> Rust 本地核心
       -> Windows 凭据库
       -> OpenAI Image API / Responses API
       -> 本地任务队列
       -> JSON/YAML 工作区
       -> 图像处理与质量检查
       -> 导出器
```

### 6.2 前端边界

React 负责：

- 页面、表单、候选比较和编辑器交互。
- TanStack Query 缓存和界面刷新。
- Zustand 保存未提交的短期编辑状态。
- Konva 画布交互和蒙版路径采集。
- 订阅 Tauri 任务事件并显示进度。

React 不负责：

- 保存或读取明文 API Key。
- 直接调用 OpenAI。
- 直接拼接不受控文件路径。
- 决定最终硬约束是否通过。
- 持久化项目和运行记录。

### 6.3 PlatformGateway

现有前端 `api/` 模块不直接散布 `invoke` 调用。新增统一 `PlatformGateway` 接口，按领域拆分项目、风格、生产、序列、任务、设置和导出方法。

开发和测试可注入内存 Fake Gateway；正式桌面应用使用 Tauri Gateway。这样可以保留现有 React Query hooks 的大部分调用方式，同时消除 `/api/v1` 和 HTTP 客户端依赖。

### 6.4 Tauri 本地核心

Rust 核心按领域模块划分：

- `settings`：非敏感设置和模型配置。
- `secrets`：Windows 系统凭据库访问。
- `workspace`：项目、路径守卫、原子写入和版本兼容。
- `providers`：OpenAI 图片和评审供应商适配器。
- `jobs`：单机异步任务、取消、重试、中断恢复和事件。
- `production`：静态资产阶段式生产管线。
- `sequences`：动画和特效网格生产管线。
- `image_processing`：背景、Alpha、裁切、缩放、留白和锚点。
- `quality`：硬约束、风格报告和漂移指标。
- `export`：无覆盖导出和哈希校验。

命令层只做输入校验、调用领域服务和映射错误，不承载生产规则。

图像处理、工作区和任务系统最终全部迁移为 Rust 本地模块。正式应用不启动 Python Sidecar，也不通过子进程调用现有 FastAPI 或 Python 服务。现有 Python 代码只在迁移期间作为独立的行为基准和黄金测试生成来源，不进入发行包。

## 7. API Key 与安全边界

- API Key 保存到 Windows 系统凭据库，不写入 `.env`、JSON、YAML、日志或前端状态。
- React 只能读取 `configured: true/false`，不能读取密钥内容。
- OpenAI 请求只从 Tauri 本地核心发出。
- 供应商审计记录保存脱敏参数、模型、尺寸、质量、候选数、请求 ID 和用量。
- 参考图、蒙版和生成结果只允许位于当前项目工作区或经过校验的只读素材源。
- 所有工作区路径执行规范化、符号链接和越界检查。
- 导出默认拒绝覆盖，写入后重新读取并校验哈希。

## 8. gpt-image-2 集成设计

### 8.1 接口选择

- 单轮生成和编辑使用 Image API，显式指定 `gpt-image-2`。
- 文本生成使用 image generations。
- 参考图编辑和蒙版重绘使用 image edits。
- 多轮对话式编辑不是 V1 主流程；候选父子运行由本地工作区记录。
- 结构化规划和视觉评审使用可配置文本模型及 Responses API。

基础图片生成不强依赖评审模型。用户关闭规划/评审时，平台仍可通过确定性提示词编译器调用 `gpt-image-2`。

### 8.2 参数规则

- 候选数限制为 1-4。
- 草稿默认 `quality: low`。
- 确认稿允许 `medium` 和 `high`。
- 输出请求统一使用 PNG。
- 产品层参考图限制为 0-4 张，以控制认知负担、请求体和运行记录。
- 模型画布和最终输出画布分离。

调用前必须检查：

- 宽高均为 16px 的整数倍。
- 最大边长不超过 3840px。
- 长短边比例不超过 3:1。
- 总像素处于 655,360 至 8,294,400 之间。

### 8.3 透明资产

`gpt-image-2` 当前不支持透明背景。透明资产固定采用：

```text
纯色或可分离背景生成
-> 边缘连通背景移除
-> Alpha 边缘清理
-> 主体裁切与共享缩放
-> 留白和锚点对齐
-> RGBA 与透明残留检查
-> PNG 导出
```

### 8.4 错误处理

- 认证和权限错误：停止任务并引导重新配置密钥或组织权限。
- 限流和 5xx：按有限退避策略自动重试。
- 超时：保留运行记录，允许用户手动重试。
- 内容拒绝：不自动重复相同请求，提示修改需求或参考图。
- 参数错误：在产生模型费用前由本地校验阻止。
- 结构化输出错误：允许重新执行规划或关闭智能评审继续基础生产。

复杂生成可能持续较长时间。任务通过 Tauri 事件报告阶段、进度、错误和完成状态；窗口关闭或应用异常后，已保存运行在下次启动时标记为 `interrupted`。

## 9. 工作区与数据兼容

继续使用现有工作区语义，但不把可写数据放在应用安装目录。正式应用的默认工作区根目录为：

```text
%USERPROFILE%\Documents\AiArtAgentPlatform\
```

用户可以在设置中选择其他本地目录。Tauri 只在应用配置目录保存当前工作区根路径等非敏感设置；API Key 仍只保存到 Windows 系统凭据库。

工作区内部结构保持：

```text
data/workspaces/<project-id>/
  project.yaml
  style-pack/
  constraints/
  assets/
  jobs/
  logs/
```

迁移原则：

- 不批量覆盖旧任务和运行文件。
- 使用 `schema_version` 和兼容读取器处理历史记录。
- 首次迁移前创建项目级备份清单和哈希清单。
- Tauri 读取现有项目时只补充缺失的新字段，不改变旧生成结果。
- 历史 FastAPI URL、端口和 SSE 状态不写入新工作区协议。
- 提供“导入现有工作区”，允许用户选择当前 `Tools/AiArtAgentPlatform/data/workspaces/` 或其中的单个项目目录。
- 导入默认复制到新工作区；只有用户明确选择“原位使用”时才直接使用旧目录。

## 10. 从现有平台迁移的方法

迁移不采用一次性重写。按以下顺序替换边界：

1. 建立 Tauri 外壳、凭据存储、设置和应用生命周期。
2. 引入 `PlatformGateway`，让前端从 HTTP API 解耦。
3. 迁移项目、风格包、参考图库和文件工作区。
4. 迁移任务队列、事件、恢复和供应商审计。
5. 迁移 `gpt-image-2` 生成、参考图编辑和蒙版编辑。
6. 迁移四类静态资产生产闭环。
7. 迁移轻量编辑器后端操作和确定性图像约束器。
8. 迁移动画和特效序列。
9. 完成数据兼容、Windows 打包和真实模型验收。
10. 删除 FastAPI 启动、端口、SSE 和 Python 运行依赖。

现有 Python 实现作为行为基准。每个迁移模块使用相同输入、黄金图片、JSON 报告和错误场景对比结果。迁移一个领域并通过等价测试后，前端才切换到对应 Tauri Gateway 方法。

最终发行包不得携带或启动 FastAPI 服务。Python 后端目录在所有功能完成等价迁移后再删除，避免迁移期间失去可比对实现。

## 11. 测试策略

### 11.1 Rust 与领域测试

- 路径越界、符号链接和非法 slug。
- 原子写入、中断恢复和版本兼容。
- API Key 不进入公开状态和日志。
- OpenAI 参数映射、错误翻译和有限重试。
- 背景移除、Alpha、裁切、缩放、留白和锚点黄金测试。
- 动画切分、共享缩放、基线和 Sprite Sheet。
- 导出无覆盖和哈希一致性。

### 11.2 前端测试

- 项目创建、切换和刷新恢复。
- 六类资产任务入口。
- 付费调用确认和非法画布门禁。
- 候选对比、选择、风险确认和继续编辑。
- 蒙版编辑器操作和请求内容。
- 序列播放、锚点、基线和漂移显示。
- 任务失败、取消、重试和应用重启恢复。

### 11.3 端到端测试

- 使用 Fake Gateway 验证完整离线工作流。
- 使用本地假 OpenAI 响应验证 Tauri 命令和事件。
- 真实 API Key 验收只由用户主动触发。
- 真实验收至少覆盖文本生成、多参考图编辑和蒙版编辑。
- Unity 导入和 Play Mode 验收仍作为独立任务执行。

## 12. V1 验收标准

- 应用为 Windows 单机程序，无 FastAPI、无本地 HTTP 端口。
- `gpt-image-2` 文本生成、参考图编辑和蒙版编辑均有真实成功证据。
- API Key 不出现在前端、项目文件、日志和构建产物中。
- 六类资产均可创建任务；四类静态资产先完成完整闭环。
- 所有正式导出通过尺寸、PNG/RGBA、Alpha、命名和边界硬检查。
- 动画与特效通过帧数、网格、共享缩放、锚点和漂移检查。
- 应用重启后可以恢复项目、任务、候选、失败和中断状态。
- 历史项目和生成结果可以读取，不被静默覆盖。
- 参考素材源保持只读。

## 13. 项目约束

本设计只涉及 `Tools/AiArtAgentPlatform/` 和平台文档。它不修改 Unity Scene、Prefab、GameObject、Component、Inspector、玩法代码或三条核心时间规则。

旧主计划和方案 B 文档保留为历史记录。它们关于功能闭环的结论仍可参考，但 React + FastAPI、HTTP API、SSE 和 `.env` 密钥读取等目标架构假设，由本设计取代。
