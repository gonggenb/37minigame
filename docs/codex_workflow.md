# Codex 工作规则

## 1. 基本规则

Codex 每次执行任务前，需要先阅读项目根目录的 `AGENTS.md`。

如果任务涉及玩法实现，还要阅读：

- `docs/project_core.md`
- `docs/gameplay_systems.md`
- `docs/unity_tech.md`

如果任务涉及任务拆解或下一步计划，还要阅读：

- `docs/task_prompts.md`

开始执行前必须先声明本轮任务类型：脚本开发任务、Editor 工作任务或测试任务。一次任务只能属于一种类型。

## 2. 任务类型

### 2.1 脚本开发任务

允许使用终端和文件读写工具创建、修改、删除源码、测试脚本、配置文本和开发文档。

本阶段不得调用 Unity MCP，不得改动 Scene、Prefab、GameObject、Component 或 Inspector，不得启动 Play Mode 或运行游戏。即使脚本需要后续挂载，也只能在交付说明中列出，不能在同一任务继续完成挂载。

### 2.2 Editor 工作任务

用于通过 Unity Editor 设置 Scene、Prefab、GameObject、Component、Inspector 引用和资源导入配置。

本阶段只做编辑器配置，不修改脚本，不进入 Play Mode，不执行游戏测试。若发现脚本缺失或错误，应停止并报告需要退回脚本开发阶段处理。

### 2.3 测试任务

用于通过 Unity MCP 运行 EditMode、PlayMode 或实际游戏流程，读取 Console 和运行状态，验证当前版本。

本阶段只测试和记录结果，不修改脚本、Scene、Prefab、Inspector 或资源。发现缺陷后应输出复现步骤和证据，再等待用户单独发起修复任务。

## 3. MCP 审批与告知

Editor 工作任务和测试任务需要调用 Unity MCP 时，任何 MCP 调用都必须经过以下流程：

1. 调用前向用户提出审批，说明任务类型、使用原因、计划调用的 MCP 工具或能力、目标对象、操作步骤、预期结果和可能影响。
2. 等待用户明确批准。没有明确批准时，不得读取 Editor 状态、场景层级、Console、资源或运行状态，也不得执行任何写操作。
3. 获批后，每次实际调用前告知用户本次调用的工具和目的，不得静默调用或把多个未说明的操作混在一起。
4. 调用后立即记录结果；失败时说明错误和当前 Editor 状态，不得擅自扩大操作范围。
5. 审批仅覆盖已说明的范围。若需要新增工具、切换场景、修改其他对象或改变任务类型，必须重新审批。

不得使用电脑控制工具绕过审批或代替 Unity MCP。必须依赖桌面交互的步骤，应交给用户手动完成，并提供明确操作说明。

## 4. 分阶段执行

同时涉及代码、编辑器配置和验证的完整功能，固定按以下阶段拆分：

```text
脚本开发任务 -> 停止并汇报 -> Editor 工作任务（MCP 审批） -> 停止并汇报 -> 测试任务（MCP 审批）
```

不得在一次任务中从修改脚本直接继续挂载组件和运行游戏。用户要求“完成整个功能”时，也要先说明拆分方案，本轮只执行用户确认的一个阶段。

## 5. 修改原则

每次修改必须优先保证项目可运行、可编译、可测试。

不要为了局部优化破坏核心玩法闭环。

不要擅自重构整个项目。

不要擅自更换引擎、语言、目录结构或主要框架。

不要假装完成了 Unity Editor 中的手动操作。

## 6. 范围控制

如果任务只要求实现一个系统，就只处理该系统相关内容。

如果任务只要求修 Bug，就不要新增玩法。

如果任务只要求整理结构，就不要改变核心规则。

如果确实需要调整范围，必须说明原因和影响。

## 7. 禁止默认接入

除非用户明确要求，否则不要接入：

- 真实广告 SDK。
- 真实支付 SDK。
- 后端服务。
- 账号系统。
- 联机系统。
- 排行榜系统。
- 云存档。
- 大型第三方框架。

可以做接口预留或文档说明，但不要实际接入。

## 8. 核心规则验证

每次涉及流程、战斗、计时、地图、洞穴、Boss 的修改后，都必须验证：

- 普通战斗期间，主地图 60 秒倒计时是否继续。
- 隐藏洞穴内，主地图 60 秒倒计时是否暂停。
- Boss 战是否独立于主地图 60 秒倒计时。

## 9. Unity Editor 操作说明

如果某项功能需要 Unity Editor 手动设置，完成回复必须说明：

- 需要创建的 GameObject。
- 需要挂载的脚本。
- Inspector 需要绑定的字段。
- 需要拖入的 Prefab、UI 或配置引用。
- 推荐的 Play Mode 验证步骤。

不要用“已绑定”“已配置”等措辞描述 Codex 无法实际完成的 Editor 操作。
